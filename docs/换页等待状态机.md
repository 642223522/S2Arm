# Android 拆线程换页等待：原生单一权威

期限只归 WSI 租约内的原生 `s2a_backing_wait`。外壳 onResume/onPause 直接调用 `s2a_wsi_set_foreground`，与登记、推进、撤销和裁决共用租约 mutex；所有取时只用 `CLOCK_MONOTONIC`，且在取得该锁后进行。恢复回调当场重置 start/progress，观察者首次读取、迟到或先后顺序都不能重置。foreground/stopping 只读租约本身，期限层不再缓存生命周期。锁内只做常数次状态运算与取时，不做日志/磁盘 I/O、分配、驱动调用或等待渲染线程；轮询睡眠在锁外。

## 事务与接口

| 状态/事件 | 权限与结果 |
|---|---|
| Begin | native 已持 serial/epoch；请求对 GPU 可见前申请一次非零 token，登记时建立原生 start/progress。活动的同 epoch token 不能被迟到首次发布抢占。 |
| Prepared(1) → Replaced(2) → Finished(3) | 托管仅持 token、单向 stage、closed；Enter 不回退，Pulse 只接受当前阶段；整事务不经空槽交接。推进到达原生时打时间戳；晚于原生准入期限的报告不能复活已失效预算。 |
| Close | 正常 End 确认 Finished 后，或 Wait 主体异常/局部 finally，由持 token 者撤销一次；旧 token/错误 writer 不能续期、关闭或重开新 owner。撤销不算推进。 |
| Fail/Stop | 锁存首错并请求停止，不设置 Prepared/Replaced/Finished，不自动 Close；未完成握手仍可保留 owner/GPU。后台等待自身不超时；租约未停止且恢复后，等待者读到原生超时才关闭；stopping租约保留至进程退出。 |

同版 ABI：`uint64_t backing_progress(uint64_t owner, int advance)`；owner=0 且 advance=1 登记，advance=1 上报推进，advance=0 关闭。`int backing_decision(owner)` 只返回 0继续、1无推进超时、2总超时、3已撤销；不向托管导出起点、age、期限或生命周期快照。托管每100ms轮询信号，推进变化时上报；按原生裁决继续/抛错，没有本地 idle/total/恢复时钟或最后250ms等待。250ms宽限也由原生计算。GAL 通用卡住看门狗仍为既有前台2s+250ms，与本换页协议的3s等待余量保持。

## 原生期限

| 情况 | 裁决/期限 |
|---|---|
| 托管读取裁决，前台 | 无推进3s+250ms，或登记起30s+250ms，先到者超时；阶段交接/观察不赠送预算。 |
| native serial 准入，匹配 writer epoch | 同一原生 start/progress，分别加1s余量：min(progress+4s,start+31s)。给托管先诊断的机会；不是另一套计时。 |
| 后台/停止 | 无限失效期限；独立100ms futex唤醒片不写入失效预算。 |
| 恢复 | 回调在同一锁内用当时 CLOCK_MONOTONIC 同时重置 start/progress；哪侧先/晚观察均不影响。 |
| 关闭后的同 epoch 准入 | 原生保留最后预算直到新事务取代；新 contender 同样可读，不依赖自己是否缓存过发布。托管得到已撤销。 |
| epoch变化（含0交接窗口） | gate 清旧预算准入资格；曾扩展者给新阶段原2s；无匹配发布不能继承旧后台/推进权限。 |
| 成功取得 serial | 旧 writer 生命周期权限结束；扩展过者从取得时给自身 roster/停稳原2s，false保留原始deadline。 |
| 无发布/false/独立core无host符号 | 原2s行为；false不创建本协议发布。 |

超时/停止仍先撤销准入安全承诺，再过活动 epoch barrier，不能越过旧 writer 返回 guest；停止永久 park。WSI 退休和租约 Stopping 都不补齐换页握手，不证明映射完成。最终进程退出由宿主收局负责；未证明退休的 GPU/lease 保留到退出。Wait 初次 Enter 在 try 外，Begin 初次登记先于请求可见；这些异常边界不保证自动 Close。

## 验证边界

- 托管11事件/深6，1,771,561路径/10,629,366步，执行生产 Enter/Pulse/Close/Decision，覆盖迟到阶段、旧Pulse、Close及四种不透明裁决；没有时钟模型。
- `writers-gate/renew_model.py`：完整生产 WSI回调、期限函数和gate适配器与独立oracle逐步对拍。20事件/深6覆盖登记/推进/撤销、错误token、新/零epoch、后台/恢复、漏观察35s周期、迟到2.5s读取、30s持续推进、边界3.25s/1s、两侧观察、Stop与admitted。读操作无状态重置；时间跳跃两步可触31s cap。不是无界进程证明。
- R7两个旧码反例保留红证据；`DelayedResumeObservation` 用真实Runtime并可联合真实Linux ARM64 gate，两种观察顺序均晚2.5s读取，超时仍从恢复回调算；`authority_races.c` 在真实生产取时内部让另一pthread尝试外壳回调，核读/登记均被同一mutex串行，后台35s后恢复不携带陈旧时间。
- 删cap、删后台暂停、删恢复重置、读时错误重置、陈旧恢复时间、owner/epoch校验及撤销保留等原生负控必须命中模型具体反例；gate另保留删准入/删续期及线程身份/发布负控。
- 真实 Begin/RunThreaded/RenderMain/Fail/Stop、迟到 Prepared/Replaced、后台32s、失败保留、serial后G锁350ms、撤销后后台/恢复、Stop/barrier/永久park由联合/真实gate回归验证，不冒充模型中的驱动行为。共享页只替换进程内host边界，并执行同一原生期限代码；Linux/glibc与NullRenderer不是Android/Bionic、Vulkan或游戏验收。


## 首个 Surface 的冷启动等待（S0 生命周期修复）

首个 Vulkan Surface 创建前若外壳已切后台，WSI consumer 使用同一 NativeLease 的有界wait片等待可用foreground generation；没有VkSurface/chain的撤销take只能在ledger允许时release+ACK，不能让UI的surfaceDestroyed卡在一份从未投入GPU的引用上。此等待没有伪造present或完成任何换页stage。普通运行期继续用原Poll/retirement状态机。

GPU启动的30s限制只计同一producer生命周期epoch内的连续前台时间；后台与epoch变化清该启动预算，避免冻结/恢复被当驱动挂死。这是guest尚未准入时的启动限制，**不是**换页publication的计时/裁决，不改变上面的native Begin/Prepared/Replaced/Finished、31s准入、恢复回调取时和owner权限。

HostApi首次stop在既有stop_lock内观察guest是否已准入。仅尚未准入时向WSI标stopping/唤醒首Surface等待；已准入guest保持原先park producers → drain → WSI退休顺序。主机测试执行生产stop/admit方法与128次双线程竞争，不等同Android冻结、驱动或GPU退休证明。
