# 触屏直通：把手指直接写进 Switch 触摸屏

状态：候选实现，iPhone 17 Pro Max + Into The Breach 实机验证通过（游戏自带触屏 UI 可正常点选）；多指手势与其它游戏的触屏 UI 未验。与 F01 的关系：F01 管虚拟按键的矩形，本条是**另一条输入链路**，不改变任何按键几何。

## 问题

游戏请求了触摸屏，S2Arm 从来没回应。设备日志开机 66 ms：

```
00:00:00.066 |S| ServiceHid ActivateTouchScreen: Stubbed. {appletResourceUserId: 1}
```

`ActivateTouchScreen` 把 `Hid.Touchscreen` 的 16 条共享内存条目初始化成空状态，之后靠宿主每帧写触点。全仓只有上游 `Ryujinx.Input/HLE/TouchScreenManager.cs` 写这块内存，它读 `IMouse`（桌面版“鼠标左键 = 触屏”）；S2Arm 从不创建它（`CreateTouchScreenManager` 0 处调用），所以 `TouchScreenState.TouchesCount` 恒为 0。

后果在游戏侧很明显：Into The Breach 的 `main` 里有整套触屏交互（`SwitchTouchInput` / `SwitchTouchInterface`、`New touch event, touch = %d,%d`、`Button_Select_Touch_Shot`、`Touch_Tap_Anywhere`、`Touch_Store_Buy` 等），点屏幕却毫无反应；玩家只能看到“点游戏内按钮只起摇杆”。

## 两套方案，互斥

“触屏布局…”管理页第一组固定两项，选中即生效并持久保存：

| 项 | 屏幕上 | 数据面 |
|---|---|---|
| 默认布局 / 用户 JSON 方案 | 方案里的 16 个按键 + 左右浮动摇杆 | 只发 `Hid.Npads`；`Hid.Touchscreen` 恒 0 个触点 |
| 触屏直通（内置 id `touch`） | 一个按键都不画，也没有摇杆圈 | 只发 `Hid.Touchscreen`；不发布手柄 |

互斥是刻意的：按键方案若同时发触点，手指按 A / 推摇杆时会被游戏当成点按，而游戏的触屏按钮就在那些位置附近，属于纯误触。切回按键方案只能从四指长按 1.5 秒的菜单进管理页——那是菜单，不画在游戏画面上。

`touch` 与 `default` 一样是保留的内置 id，不落 JSON 文件；选择记录仍是 `Documents/VPadLayouts/.selection.json`（`{"schemaVersion":1,"id":"touch"}`），重启后保持。

## 实现

`ios/vpad.m`

- 槽位制触点：一根手指占一个固定下标（0～15），按下首帧发 `Start`、中间帧 `0`、抬手后由 HID 线程补一帧 `End`。下标固定，游戏认得出是同一根手指，所以拖拽、长按、滑动、多指都原样进游戏。
- 坐标：渲染原图按 16:9 等比 fit 进根视图，两侧留黑边；落在黑边上的按下不建槽（游戏同样收不到）。

```
gameRect = aspect-fit(16:9, bounds)          // 956×440 → 782.2×440，原点 x = 86.9
X = (pt.x − gameRect.x) / gameRect.w × 1280
Y =  pt.y               / gameRect.h × 720
```

- 纯触屏模式下 `rebuildKeys` 返回空数组、`wake` 直接返回：没有 `UILabel`、没有热点、没有能“呼出”按键的对象。接了实体手柄也保留这一层（手指与手柄是两条独立输入）。
- 按键方案：落键走按键，空白处按下即起摇杆（原生手感），`readTouches` 恒返回 0。

`ios/vpad_layout.{h,m}`

- `+isBuiltinIdentifier:` 统一判断 `default` / `touch`；`layouts`（跳过同名文件并报 `F01.identity`）、`selectedLayout`（返回 nil 不报错）、`saveLayout`（拒绝另存为内置 id）、`selectIdentifier`（免读文件）四处按内置项处理。

`ios/vpad_settings.m`

- 第一组固定两行：`默认布局` / `触屏直通`，之后才是用户方案；`触屏直通` 副标题“不显示虚拟按键，触摸操作直接交给游戏”。

`services/S2A.Services/InputPump.cs`

- 按符号查 `s2a_vpad_read_touch`（Mac 宿主没有这个导出，保持为空就完全不碰触摸屏）。
- 每次 HID 提交后 `PushTouch`：读回 0～16 个触点写进 `device.Hid.Touchscreen`。**0 个触点也写**，与桌面版鼠标路径一致；否则共享内存停在最后一次状态。缓冲 16 对应触摸屏共享内存的 `Array16`。

## 线程与生命周期

UIKit 主线程写，HID 线程约 60 Hz 读；16 槽位状态都在 `@synchronized` 内改，读侧不碰任何 UIKit 属性。以下情况清空触点并补一帧 `End`：失焦、进后台、改布局、开管理页、实体手柄状态切换、尺寸/安全区变化。管理页打开期间不写触点。

## 验证

- `xcrun clang -fsyntax-only -fobjc-arc -Wall` 三个文件零警告；`dotnet build services/S2A.Services`（Release）0 警告 0 错误。
- 出包后在 iPhone 17 Pro Max 上覆盖安装，选“触屏直通”：`host.log` 打 `触屏布局：纯触屏（不显示虚拟按键，手指直接交给游戏）`，屏幕上无任何按键；点机甲、点目标格、点确认均按触屏逻辑响应，选中高亮与指令确认正常。
- 选回“默认布局”：16 键与摇杆照旧，摇杆按下即动；此时点游戏内的触屏按钮无任何反应（游戏只看得见手柄）。
- 双击左/右半屏后按住 → LS/RS 仍生效。

## 已知限制

- 纯触屏方案没有按键，也没有摇杆：取消/返回、移动光标这类只认手柄键的地方必须切回按键方案，入口只有四指长按 1.5 秒。
- 按键方案下整层屏幕都是手柄区，游戏触屏按钮点不到（这是上一项的另一面）。
- 只做触点传输，不做手势识别；多指上限 16。
- 未验：其它游戏是否依赖“无手柄”才亮触屏 UI。若某些移植版只在掌机模式且无手柄时启用触屏，纯触屏方案可能还需要不发布虚拟手柄（当前仍发布，只是按键不显示）。
