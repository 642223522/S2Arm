# 原生层排查手册 ③：系统服务回答不对

适用：游戏不崩，但行为不对：
- 卡在加载、读到错的资源；
- 存档丢了或写坏；
- 时间跳变；
- 联机看不到对方；
- 游戏 Break 的结果码落在某个服务模块。

服务层是 C#：services/S2A.Services，以及 compat/tree 里的 Ryujinx.HLE / Ryujinx.Horizon。

配套：[① 崩溃](原生层_崩溃.md)、[② 进不去 / 游戏 Break](原生层_进不去与Break.md)、skill [native-triage](../../skills/native-triage/SKILL.md)。

## 1. 看哪几行

| 行 | 出处 | 意思 |
|---|---|---|
| `【红】未实现服务命令 <服务类> 命令 <号>（第 n 次）` | services/S2A.Services/HleTarget.cs | 服务认识，但这个命令号没实现 |
| `【红】未实现服务 <名>` | services/S2A.Services/SmDirect.cs | 游戏要的服务整个没有 |
| `【红】未实现服务：…`（退出时的汇总行） | services/S2A.Services/Red.cs | 本局所有没实现的（服务，命令）；没有时打「未实现服务：无」 |
| `【红】未实现：系统调用/0x…` | runtime/src/gate.c | 内核调用没实现 |
| `【红】Horizon 服务 <名> …异常` | services/S2A.Services/HorizonHost.cs | Ryujinx.Horizon 的服务线程抛了异常 |

- 同一个（服务，命令）首次必打一行，之后在第 2^n 次再打。只看计数就能知道游戏是不是在反复重试。
- `S2A_STRICT=1`：首个红行就 FailFast，并带出托管栈。用于把「一直重试」变成「当场停」，方便抓调用点。

## 2. 常见根因（都是踩过的）

| 现象 | 根因 | 修法 |
|---|---|---|
| 多个会话并发读 RomFS，偶发读错数据但返回成功（#883） | 所有数据存储会话共用同一个读位置字段 `_pos` | 每个进程登记一份按偏移读的 IStorage，各会话拿不占有的视图（已修，compat/patches 里的 romfs-one-storage） |
| 设备睡眠 / 切后台回来，游戏时间跳或卡住 | 宿主时钟在睡眠时停了，客体稳态时钟没补上看不见的那段 | 唤醒 / 解冻后补上「连续时钟 − 客体时钟」（runtime/src/os.c 的追赶钩子 + Ryujinx TimeManager） |
| 收局线程上服务空引用 | Ryujinx.Horizon 的 `[ThreadStatic]` 静态量在新线程上是 null | 见手册 ① §3.1 |
| 大写入时长度对不上（#932） | `IFile.Write` 把 64 位缓冲长度强转成 `int` | 按上游语义校验并拒绝，不截断 |
| 首次联机看不到对方（#924） | iOS 弹本地网络权限框时，系统可能直接拒掉本次发现操作，我们不重试 | 失败后退避重试，回前台重启发现 |

共同点：每一条都是「我们给游戏的回答和真机不一样」，而不是游戏有 bug。

## 3. 怎么对齐 Ryujinx 真值

1. 找到游戏调的那个命令：服务类名 + 命令号。
   - Ryujinx.HLE 里的服务搜 `[CommandCmif(<号>)]` / `[CommandTipc(<号>)]`；
   - Ryujinx.Horizon 里的服务搜 `[CmifCommand(<号>)]`；
   - 结果码查 `Ryujinx.Horizon.Common/ResultNames.cs`。
2. 判断它是上游原样，还是被我们改过：
   - 对 `compat/patches/` 里改到这个文件的补丁做 diff；
   - 补丁的上下文行就是上游原文；
   - `compat/改动清单.md` 列了每个补丁改了什么、为什么改。
3. 上游就是真值。我们的改动只允许处理宿主差异：地址只剩几百 MB 所以不另开大数组、线程模型不同、页保护不同。**游戏能看到的返回值、结果码、写回缓冲的内容，都必须和上游一致。**
4. 上游本身也没实现：照 Switch 真机行为补（Switchbrew 等公开资料），并在 PR 里写明依据。拿不准时，宁可报红，不要回成功。
5. 改 Ryujinx 的代码一律走新补丁（`compat/patches/<日期>-<名>.patch` 并加进 `series`），同时登记 `compat/改动清单.md`。不要直接改 tree 而不留补丁。

## 4. 单测

- 位置：`services/S2A.Services.Tests/`（入口 Program.cs，已有大量现成样例，可以照着写）。
- 写法：
  1. 构造最小的请求：假的缓冲描述、两个线程、两个会话……；
  2. 断言**返回内容逐字节**和期望一致，不能只核结果码和耗时。#883 原来的单测只核了耗时，所以没抓到读错。
- 并发类问题：两个线程、各几千轮、逐字节比对原文。期望值取自原始文件，不取自被测实现。
- 反证：把修复回退，测试必须红，PR 里贴读数。
- 新测试要能被门禁调到：`bash tests/test_wired_test.sh` 全过。
