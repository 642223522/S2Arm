# 排查手册：直连异常 / 退回通用

适用范围：游戏没走直连（NVN / Vulkan / OpenGL 前端直接翻成 Metal），而是跑在通用模式（Ryujinx GPU 模拟）上；或者走了直连，但出现直连异常、现编失败、着色器取码报红。花屏看 [花屏与贴图错](花屏与贴图错.md)，宽屏看 [不满屏与宽屏异常](不满屏与宽屏异常.md)。

结论先行：「退回通用」几乎都不是运行时决定的，而是**包里根本没有可用的直连库**。先看 host.log 第一条「图形模式」行的依据，再回头查出包期的直连库阶段。目标是直连覆盖 100%：每一款不是直连的，都要有一条已立项的缺口，不许静默退回通用。

## 直连库是什么

出包期产出，放在产物根的 `shaders/` 下：

| 前端 | 目录 | 说明 |
|---|---|---|
| NVN | `shaders/direct/b-<链号>/lib.idx` | 链号 = 着色器翻译链的版本号，宿主只认与自己同链号的库 |
| Vulkan | `shaders/direct/vk/` | 运行时 SPIR-V 款：出包期抓着色器离线出库，设备上兜底 |
| OpenGL | `shaders/direct/gl/` | 同上 |

设备上现编（运行时现场翻译、编译）只当安全网，不能当主路。

## ① 症状长什么样

这份没有合适的截图：通用模式的画面本身往往正常，问题在性能和首遇卡顿。下面用 host.log 原文示例代替。

```
[s2a] 图形模式：通用（依据 环境变量 S2A_GFX=generic；程序号 0100581007068000）
[gal] 【红】管线归档与本机不匹配：本机型号 …、架构 …；包里有：无——包里没有任何管线归档。首遇全部现建
```

正常走直连的样子：

```
[s2a] 图形模式：直连（依据 包里带本宿主口径的直连库（NVN b-<链号> 或 Vulkan vk/）；程序号 …）
```

快测 / 普查起局前的退回提示（维护方进局检查退出码 5）：

```
🟡 待直连根 t0100581007068000 handheld：根 … 没有本链 <链号> 的直连库（有：无），向出包运维线要当前链号的根；不起局
```

## ② 用哪个工具、看哪几行

| 看什么 | 行 / 工具 | 怎么读 |
|---|---|---|
| 图形模式与依据 | `[s2a] 图形模式：直连 / 通用（依据 …）` | 依据写「环境变量 S2A_GFX=generic」= 起局工具强制的，回头查直连库；写「包里带…直连库」= 正常直连 |
| 现编汇总 | `直连着色器现编汇总：成功 a、失败 b、跳过 c、复用上局 d、输出类型变体 e（…）` | b > 0 要查；a 大说明库不全，首遇在设备上现编 |
| 库不在包里的键 | `【红】 shader <键> is not in the shader map (DM_NVN_SHDUMP=directory …)` | 开 `DM_NVN_SHDUMP=<目录>` 把缺的着色器存成 `<键>.ctl` + `<键>.code`，离线复现翻译 |
| 链接版桩 | `linked stand-ins: no stub archive / function bodies for this device (…)` | 本机型号没有对应的链接版桩，首遇只能整编 |
| 着色器取码 / 翻译异常 | `【红】` + `S2AShaderFault` 分类（取码越界 / 翻译失败）、地址链 ①②③ | 防线接住后只跳过这组绘制，红行带各阶段 GPU 地址 / 读取长度、物理段、宿主页写跟踪状态 |
| 普查总表 | `tools/census/census.py` 的「图形模式」「直连异常」两列 | 批量看哪些款没走直连 |

快测里退回通用的逻辑在 `tools/quicktest/one_game.sh` 的 `mac_once`：进局检查退出 5（根里没有本链直连库）就改起通用局，并把原因留在 `entry*.direct_missing`。所以只要普查总表里「图形模式 = 通用」，第一件事就是去看出包期为什么没出库。

## ③ 常见根因（现象 → 根因 → 怎么认出来 → 修在哪）

### 1. 包里一份直连库都没有（最常见）
- 现象：图形模式通用，依据是 `S2A_GFX=generic`；`entry*.direct_missing` 里写「有：无」。
- 实例：普查批次 c1029b，起局的 14 款里 9 款直连、5 款通用（失落城堡、ShakesOnAPlane、Servonauts、泰拉瑞亚、浪漫沙加3）。5 款全是这个原因。
- 下一步，按类定性为什么出包没出库：
  - 不是 NVN 游戏，用 Vulkan / GL：查 NSO 的导入符号（`nvnBootstrapLoader` / `vkGetInstanceProcAddr` / `eglGetProcAddress`）；
  - 着色器来源找不到：出包期从游戏数据或程序里抽着色器，抽到 0 支，要先认引擎（Unity / UE / FNA / 自研）；
  - 翻译或编译失败：哪一步、哪类指令；
  - 运行时才生成着色器。
- 状态：这 5 款的逐款分类正在做，结论出来后补进本节。

### 2. 链号对不上
- 现象：根里有 `b-<旧链号>`，宿主要的是新链号，同样退通用（提示里「有：」后面列着旧链号）。
- 根因：着色器翻译链改过之后，旧包的库不再被新宿主承认。
- 修在哪：重出包。改翻译链的提交要走换链窗口，统一换链、统一重出。

### 3. 出库不齐
- 现象：出包时报「直连库出库失败（… 出的库不齐，旧库不动）」。
- 实例：神之天平 外传。
- 修在哪：直连库出库脚本（`translator/` 下的 dmsh 一族）。先看哪些键缺，再查对应翻译步骤。

### 4. 直连异常（走了直连但跑不对）
- 现象：普查「直连异常 = 是」（例：Sayonara Wild Hearts）。
- 做法：按 ② 的现编汇总、库外键、取码报红三类读数逐项看。

### 5. 着色器取码读到垃圾
- 现象：GPU 线程抛异常、整局卡死或崩（例：双人成行，偶发，没稳定复现）。
- 根因：着色器地址上的字节是旧的或越界，翻译时抛 `Invalid shader stage` 这类异常。
- 现状：防线已合入（main 94b777d9a）。取码或翻译抛的任何异常都只报红一次、跳过本组绘制，GPU 线程不退出。红行带地址链，可以交原生层定因；带红的款不能登记，以根修为准。
- 修在哪：`compat/tree/src/Ryujinx.Graphics.Gpu/Shader/ShaderCache.cs`、`Engine/Threed/StateUpdater.cs`、`Engine/Compute/ComputeClass.cs`，对应补丁在 `compat/patches/`；写跟踪查询 `s2a_track_page_info` 在原生层。

### 6. 首遇卡顿被误当成直连问题
- 现象：直连能跑，但第一次画到某个着色器时卡几十到几百毫秒。
- 根因：库里没有这支（现编），或者设备代际要的变体不在库里（例：Apple9 上采样器偏置 / 归约要模拟）。
- 怎么认：现编汇总里的成功数；`pipeline prewarm list … N lines`；`shader loads: requests … / constructions …`。
- 修在哪：出包期把它补进库，不要靠设备现编。
- 帧率 / 能耗问题（慢帧当帧归因、帧率格、能耗格）看 [帧率低与耗电高](帧率低与耗电高.md)。

## ④ 代码在哪、单测怎么写

| 区域 | 文件 |
|---|---|
| 图形模式判定、起局退回 | `runtime/`（「图形模式：」那一行）、`tools/quicktest/one_game.sh` |
| 直连 NVN 后端 / 着色器加载 / 现编兜底 | `graphics/nvn/gfx/nvn/nvn_mtl.m`（`shader_load_depth`、`DM_MSL_FALLBACK`、`DM_NVN_SHDUMP`） |
| 直连库出库 | `translator/`（dmsh 一族） |
| 通用模式着色器取码防线 | `compat/patches/`（对应 `Ryujinx.Graphics.Gpu/Shader/`） |
| 普查 | `tools/census/census.py` |
| 方案 | `快速通用模式方案（维护方内部文档）` |

先红后绿样板：

- `tests/shader_garbage_guard_test.sh`：让生产路径真的抛 `Invalid shader stage`，修前红，修后断言不抛、红行恰好 1 条且带 ①②③。
- `tests/shader_fault_cache_test.sh`：取码越界的报红缓存。
- `graphics/nvn/tests/t_nvn_shader_flight.m`：直连着色器并发加载，覆盖同身份只构造一次、失败后可重试、首次使用只记一行。
- 翻译器类问题：用 `DM_NVN_SHDUMP` 存下的 `.ctl` + `.code` 做离线输入，写一个翻译单测。修前报错，修后翻出的 MSL 能编过，必要时再加 GPU 输出对拍。
