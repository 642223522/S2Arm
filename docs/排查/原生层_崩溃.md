# 原生层排查手册 ①：崩溃（含收局崩）

适用：进程异常退出、host.log 有 `【红】CRASH 信号` 行、iOS 上闪退。只讲原生层 / 服务层（runtime/、services/、compat/ 的非图形部分）；画面类问题不在这里。

配套：[② 进不去 / 游戏 Break](原生层_进不去与Break.md)、[③ 系统服务回答不对](原生层_服务回答不对.md)、skill [native-triage](../../skills/native-triage/SKILL.md)。

## 1. 症状

| 现象 | 多半是 |
|---|---|
| 退出码 134（SIGABRT） | C# 未处理异常 / `Environment.FailFast` / 原生 `die()` |
| 退出码 139 / 138（SIGSEGV / SIGBUS） | 碰了没映射或不该碰的地址：远端翻译失败、窗口外地址、已释放对象 |
| 退出码 132（SIGILL） | 执行了苹果用户态不认的指令：改写器漏掉的系统 / 异常类指令，或游戏自己的 `hlt`（两边都陷入终止，见 §3.3） |
| 退出码 133（SIGTRAP） | 游戏自己的 `brk`（断言）；或本仓库的诊断钩子没认领 |
| 到 MARK 之后、「优雅退出」之后才崩 | **收局崩**：先按 §3.1 查 |
| iOS 闪退、host.log 没有 CRASH 行 | 被系统杀：看下一次启动时「诊断包：MetricKit 交来」那一行的退出原因（内存超限 / 看门狗 / CPU） |

## 2. 先看哪几行（按顺序）

1. **`【红】CRASH 信号 N 地址 A pc P lr L sp S`**（runtime/src/crash.c）：N 是信号号；A 是出错地址（SEGV / BUS 时有意义）；P / L 已经换成「模块+偏移」，宿主函数带「（宿主）」。
2. **紧跟的帧栈 `#0 … #N`**：游戏模块写成 `main+0x…` / `sdk+0x…` / `subsdk0+0x…`，宿主写成 `函数+0x…（宿主）`。帧里是**返回地址**：
   - 符号化前先减 4；
   - 显示成「某函数+0x0」的，说明调用发生在前一个函数的最后一条指令上（不返回的调用）。
3. **崩前 80 行里的 .NET 异常栈**：`System.NullReferenceException …` 后面紧跟的 `at 类型.方法() + 0x…` 就是托管侧崩点。
4. **崩点在不在收局**：前面有没有「收到 游戏 Break：优雅退出」「S2A 服务层关停」「优雅退出 X 秒」。
5. **地址类的旁证**（SEGV / BUS 时必看）：
   - 「远端 [收局]：影子区用 … 缺页 … 代执行 … 失败 N 次」：失败非 0 时，说明远端翻译接不住；
   - 「游戏地址用量 / 游戏地址峰值」：崩溃地址落在哪个区、有没有越过窗口；
   - 「低区账 [巡检]」：宿主低区地址是不是耗尽了（iPhone 上常见）。

## 3. 常见根因（都是踩过的）

### 3.1 收局崩：`HorizonHost.Stop` 空引用（已修，main 6d8e79919）
- 现象：自动玩家结束或游戏 Break 之后收局，`System.NullReferenceException at S2A.Services.HorizonHost.Stop() + 0xd8`，随后 `CRASH 信号 6`。10-29 夜间真机冷启的 12 局崩全是它：凡是含引入提交、不含修复的包，每局都崩。
- 根因：`Ryujinx.Horizon.HorizonStatic.Syscall` 是 `[ThreadStatic]`。`Stop` 在新开的收局线程上跑，这条线程上它是 null。
- 修法：`Stop` 开头在本线程补登记（`HorizonStatic.Register(Options, Syscall, …)`），不要另造一份全局状态。
- 单测：**在新线程上**调 `HorizonHost.Stop`（在主线程上调复现不出来）。
- 通用教训：Ryujinx 里凡是 `[ThreadStatic]` 的静态量，跨线程用之前都要按本线程重新登记。

### 3.2 SIGSEGV 落在窗口外 / 远端地址
- 先确认布局：「地址按需：标准布局要 X MB，宿主占到 Y MB——小区在前、别名区伸出窗口 Z MB」。伸出窗口的部分只是承诺，游戏碰到那里由远端翻译（runtime/src/far.c）兜底。
- 「远端 …失败 N 次」非 0，或者崩溃地址在窗口之外又不在远端范围内：查 far.c 的影子分配。曾经踩过的一次是：堆区影子放不下以后，没有改从宿主任意空闲地址分（已修，`g_ov_used`）。
- 「布局提示：别名优先」的款（UE4 这一类：开局就要几十 GB 的别名区）：只有这类款压小堆区和栈区，给别名区让窗口；别的款各区按 Horizon 真值给。

### 3.3 SIGILL：指令两边语义不同
- 出包时改写器会列出所有苹果用户态与 Switch 语义不同的指令（`PFRW … gaps=N`，`<模块>.gaps.tsv`）。只要有缺口，整款就不出包；能出包，说明白名单判它们两边一致。
- 白名单的依据只能是**两边逐条实测**：例如 `hlt`，苹果是 SIGILL，Switch 用户态是未定义指令异常，两边都陷入终止，所以同 `brk` 一样放行。
- 运行期还出现 SIGILL：多半是 JIT / 运行时生成的代码没过改写，看 `【红】ControlCodeMemory 映成读执行` 这一类行。

### 3.4 安卓才崩、苹果不崩：宿主直读 `PROT_NONE` 页
- 写跟踪（graphics/track）会把 GPU 改过的页设成不可读。苹果上，宿主直读这种页会被写跟踪的缺页处理接住（READFLUSH 分支：放成只读，不回写）；安卓 NativeAOT 上则是不可恢复的访问违例。
- 修法：宿主读客体内存一律走不经页保护的读钩子（`S2AReadUntracked` 那一类），不要直接 `GetSpan().CopyTo`。

## 4. 怎么对齐 Ryujinx 真值

- `compat/tree/` 是打了本仓库补丁的上游树，补丁在 `compat/patches/`（`series` 定顺序），改动清单在 `compat/改动清单.md`。
- 判断「谁对」：先读上游同一函数（补丁的上下文行就是上游原文），再看我们的补丁改了什么。**上游就是真值**；我们的改动只能是为了宿主差异（地址、线程、页保护），不能改变对游戏可见的语义。
- 修法优先「把我们的跟踪 / 回写对齐上游」，不要在调用点另外加一份补救。

## 5. 先红后绿的单测怎么写

- 原生层 C：`runtime/tests/t_<名>.c`，构建规则只新增一个分片 `runtime/tests/mk/<名>.mk`（runtime/build.mk 会自动收进来），用 `make native-test-<名>` 跑。
- 服务层 C#：`services/S2A.Services.Tests/`。
- 写法：
  1. 把崩溃时序缩到最小（哪条线程、先后顺序、什么输入），让测试**在旧代码上红**；
  2. 修完变绿；
  3. 再做一次反证：把修复回退一行，确认测试会红。PR 里贴「回退 → 红」的读数。
- 期望值必须能不跑被测实现就算出来（手算、上游行为、规范），不要拿实现的输出当期望。
- 新单测要能被门禁调到：`bash tests/test_wired_test.sh` 必须全过。确实跑不了的单测在它自己的文件头写「门禁手动：<原因>」（由 `tools/gate_decl.py manual` 收集，没有中央白名单）；接上门禁以后，删掉那行声明。
