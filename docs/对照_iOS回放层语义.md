# 新回放层对照 iOS 回放层：逐段语义表

做法（11-11 定）：新层（`graphics/nvn/replay/` + `android/native/nvn/backend_vulkan.c`）的每一段，对着 iOS 回放层 `graphics/nvn/gfx/nvn/nvn_mtl.m` 的同一段过一遍，
把 iOS 用到的每个状态字段、做的每条归一化与特殊情况列在这里，写明新层现在做了什么、差在哪。表列全之后一批实现并带用例，再上真机验收。
真机上「画错」时回到这张表找语义差，不靠加开关逐项试。后端这一侧另对照仓库里的 `compat/tree/src/Ryujinx.Graphics.Vulkan`。

状态：**进行中**。已过的段在下面；没过的段列在最后。

## 1. 管线描述（iOS：`pso_key_fill` @7909、`pso_key_norm` @7894、`pso_desc` @7806）

| # | iOS 的语义 | 新层现状 | 差 |
|---|---|---|---|

| 1.2 | 整数格式的目标从不混合（硬件忽略它的混合状态） | 后端对整数格式的目标不开混合 | 已补（11-11） |
| 1.3 | 没有格式的颜色槽：写掩码、混合开关、混合状态全清 | 后端对空槽占位不写 | 已有（C77） |
| 1.4 | 混合状态按目标号取（`blend[l]`），进键前把高级混合位清掉 | 核心清掉高级混合位再给后端 | 已补（11-11） |

## 2. 绘制时的动态状态（iOS：@12740–12776）

| # | iOS 的语义 | 新层现状 | 差 |
|---|---|---|---|
| 2.1 | 没设视口：整张目标 | 同 | 无 |
| 2.2 | 窗口原点左下：视口上下翻（图自上而下存） | 相反的约定：左下不翻（图自下而上存），上屏时翻；左上才翻 | 约定不同但自洽（C67 / C73）。**连带后果见 2.6** |
| 2.3 | 视口重排：只认「y 取反」= 视口上下翻，绕序不动；其余记红照画 | 原先整个忽略 | 已补（11-11）：「y 取反」翻视口，其余记账 |
| 2.4 | 裁剪矩形夹到目标内；交集为空的绘制跳过 | 原先原样给后端（负起点 / 超大宽高） | 已补（11-11） |
| 2.5 | 两面都剔：跳过绘制 | 后端按两面都剔建管线 | 等效 |
| 2.6 | **正面绕序 = 接口值 异或 建队列时定的「光栅翻转」位**（`s2a_nvn_rast_flip`；游戏先建队列后改窗口原点时两者不一致，曾让一款赛车游戏「正面被剔、车和赛道全黑」） | 原先后端直接用接口值，不看翻转位，也不看自己翻没翻视口 | 已补（11-11，契约 v6）：核心给规范化设备坐标里的绕序，后端按翻不翻视口换成帧缓冲绕序（C80）。原点与翻转位一致的游戏行为不变，不一致的会变 |
| 2.7 | 填充模式「线」 | 只建填充模式，记账 | 已知未接 |
| 2.8 | 深度夹取 = 关掉深度裁剪 | 原先后端整个忽略（恒裁剪） | 已补（11-11，进管线描述） |

| 2.10 | 模板读掩码 / 写掩码 / 参考值按正背面 | 同 | 无（C68） |
| 2.11 | 内部分辨率缩放、加宽（宽屏）对视口与裁剪的换算 | 没有这两项功能 | 不适用 |

## 3. 开通道（iOS：`rp_begin_ex_` @5008、`attach` @4883、`rt_dup_slot` @4797）——**过了颜色附件一半，深度模板与收尾没过**

| # | iOS 的语义 | 新层现状 | 差 |
|---|---|---|---|
| 3.1 | 同一张图的同一级同一层挂了两个颜色槽：只挂前一个 | 原先两个都挂（原生接口不许） | 已补（11-11）：后一个槽留空，管线描述同步 |
| 3.2 | 视图换了格式：按那个格式的视图挂（管线格式跟着附件）。例：经 sRGB 视图写线性存储的交换链图，硬件写入时做 sRGB 编码；挂原图会整幅偏暗 | 原先渲染通道按**原图**格式声明、图像视图按**视图**格式建，两者不一致 | 已补（11-11）：渲染通道按视图格式声明 |
| 3.3 | 当渲染目标的图建的时候没带渲染目标用途（随包贴图）：开通道前就地升级用途，保留像素 | 建图时能当附件的格式一律带附件用途（`rp_res.c usage_of`：原生接口的用途事后补不了） | 已有 |
| 3.4 | 压缩格式的图当渲染目标、深度图经颜色视图挂：走影子图 | 没有 | 缺（没走到；走到时后端报不支持） |
| 3.5 | 待折清除 → load = CLEAR，否则 LOAD；一系列「证明不用载入就不载入」的省带宽手段 | CLEAR / LOAD，不做省带宽 | 画面等效 |
| 3.6 | 只为清除开的通道只挂有待折清除的槽 | 全挂 | 画面等效 |
| 3.7 | 深度 / 模板附件各种取舍（只用模板、只用深度、都不用） | 没过 | **待对** |
| 3.8 | 通道收尾的 store 取舍、多重采样解析 | 没过 | **待对** |

## 4. 贴图内容的来源与采样事实（iOS：`tex_mtl_` @4113、`tex_cpu_content` @3900、`tex_init_fill` @3670、`tex_zero_fill` @3345、`nvn_unnorm.inc`、每款参数 `host/game_tsv.h`）——**11-11 过了「内容从哪来」这一半，视图的级 / 层 / 深度模板取面还没过**

这一段是 3D 那款「整屏洋红、物体黑剪影、界面不显示」的全部原因；每一条都是真机逐笔日志 / 读回定位到之后回来对出来的。

| # | iOS 的语义 | 新层原状 | 差 |
|---|---|---|---|
| 4.1 | 新建宿主贴图时取一次内存池里现有的内容（`tex_init_fill`）：虚拟池、随包贴图、多重采样、深度模板不取；CPU 不能访问的池里带压缩提示的不取、浮点格式带 Inf / NaN 的不取；全 0 不取 | 只认「首次使用时 CPU 写过」，且排除 CPU 不能访问的池——游戏把贴图文件读进这种池再建贴图，全部块压缩贴图一次都没传过（ASTC 读成错误色洋红，DXT 读成全透明） | 已补（11-11）。还差：按页的 GPU 写账（`gpw_stale`，过时字节不取）、判全 0 时跳过没碰过的页（`mem_any_touched`） |
| 4.2 | 不取的新图清零（`tex_zero_fill`；压缩 / 深度模板 / 多重采样的不清） | 不清（Vulkan 新图内容没有定义） | 已补（11-11） |
| 4.3 | 每款参数没有随包档时取 Switch 真实语义的缺省：条件渲染、CPU 写进池的贴图上传（flush / 脏页两条）、动态句柄着色器、段内 GPU 时间戳都开 | 新层的构建里只有诊断用的弱桩，全 0：这些全是关的 | 已补缺省（11-11）。还差：读随包 `game.tsv` |
| 4.4 | 采样坐标归一与否只看有效目标（视图设了目标取视图的）：RECTANGLE 不归一，其余一律归一，与格式无关（`nvn_unnorm.inc`） | 旧零件把整数格式一律当「纹素坐标」，翻译器给坐标再除一次尺寸——延迟光照读几何缓冲永远读到左上角一个像素 | 已补（11-11） |
| 4.5 | 着色器声明浮点、绑上来的是 32 位整数贴图：换成同尺寸的浮点视图把位原样交出（`tex_float_fit` @6770）；8 / 16 位整数没有对应浮点格式，原样绑 | 原样绑（浮点采样器读整数图，Vulkan 里未定义；这台骁龙上碰巧拿得到位） | 另支：翻译器按绑定视图的格式声明整数采样器（规范做法，安卓模拟器同此）。后端已给整数视图配最近点采样器 |
| 4.6 | 深度模板贴图按模板面采样（视图 / 贴图的深度模板模式 = STENCIL，@6553） | 没接 | 待补（这款没用到） |
| 4.7 | 贴图事实（格式、目标）取绑定视图的 | 取存储的 | 已补（11-11） |

## 8. 遮挡计数、条件渲染、计算派发（iOS：`rc_*` @893–@945、`vis_*` @950–@990、主循环 @14570–@14667、`dispatch` @13556）——**遮挡计数与条件渲染 11-11 已搬，计算派发没搬**

| # | iOS 的语义 | 新层现状 | 差 |
|---|---|---|---|
| 8.1 | 通过的样本数是队列上的累计值：复位清零、绘制往上加、报告写出当时的累计值；每个通道一个新槽，报告后换新槽，完成时求和 | 同（核心分槽，后端一段一个查询池） | 游戏第一次碰这个计数器的那一段不计（开段时还不知道要槽）；Metal 的清除走通道的 load，这边带裁剪的清除是画出来的，画之前先停计数 |
| 8.2 | 条件渲染：时间戳报告的计数值回放时按 0 算（本次提交里的、已提交没完成的），完成后以内存为准；别的计数器写过的地址当不知道、照画；不画的那一段丢绘制与清除；新提交从「画」开始 | 同 | 多重绘制、贴图绘制本来没接 |
| 8.3 | 条件渲染开着时，时间戳类报告的计数值写 0 | 同 | 无 |
| 8.4 | 计算派发：取计算程序 → 落地待折清除 → 绑定阶段 5（驱动段 c0 带派发维度 0x200、常量缓冲指针表 0x210、存储缓冲表）→ 派发；另有内置计算核、首次调用写、图像写、间接派发、共享内存溢出 | 没接（记未接） | 待搬。3D 那款真机取证：只有一种派发，1x1x1 组，读常量缓冲 0（520 字节）、读写存储缓冲 0（6144 字节），没有图像与贴图。先搬这一种要用到的：计算程序来源、存储缓冲绑定、GPU 写过的缓冲范围不被 CPU 侧镜像盖掉 |
