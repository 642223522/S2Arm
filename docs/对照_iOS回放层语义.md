# 新回放层对照 iOS 回放层：逐段语义表

做法（11-11 定）：新层（`graphics/nvn/replay/` + `android/native/nvn/backend_vulkan.c`）的每一段，对着 iOS 回放层 `graphics/nvn/gfx/nvn/nvn_mtl.m` 的同一段过一遍，
把 iOS 用到的每个状态字段、做的每条归一化与特殊情况列在这里，写明新层现在做了什么、差在哪。表列全之后一批实现并带用例，再上真机验收。
真机上「画错」时回到这张表找语义差，不靠加开关逐项试。后端这一侧另对照仓库里的 `compat/tree/src/Ryujinx.Graphics.Vulkan`。

状态：**进行中**。已过的段在下面；没过的段列在最后。

## 1. 管线描述（iOS：`pso_key_fill` @7909、`pso_key_norm` @7894、`pso_desc` @7806）

| # | iOS 的语义 | 新层现状 | 差 |
|---|---|---|---|
| 1.1 | 片元着色器没写的颜色输出：该目标写掩码清 0、不混合（硬件只写着色器输出表里的目标，其余不动；`fs->rf.color_mask`） | 核心原样把 `chmask` / `blend_en` 交给后端；后端照写 | **缺**。Vulkan 上着色器没写的附件内容未定义，开着混合时会把未定义值混进去。需要编译结果给出片元输出掩码 |
| 1.2 | 整数格式的目标从不混合（硬件忽略它的混合状态） | 后端按 `blend_en` 位照开 | **缺**。整数附件开混合在 Vulkan 上非法 |
| 1.3 | 没有格式的颜色槽：写掩码、混合开关、混合状态全清 | 后端对空槽占位不写 | 已有（C77） |
| 1.4 | 混合状态按目标号取（`blend[l]`），进键前把高级混合位清掉 | 核心拷 `rp_S.blend[8]`；后端遇 `adv_mode` 报不支持 | 部分：高级混合位应在核心清掉再给后端，否则同一画面效果的管线因这几位失败 |
| 1.5 | 透明测试（`color.alpha_func` 1–7）走片元着色器变体；参考值是绘制时的状态（`OP_ALPHA_REF`） | 编译事实带了比较函数，**参考值写死 0** | **缺**。`rp_S.alpha_ref` 要进编译事实与身份（或走支持缓冲），否则带透明测试的几何体判据错 |
| 1.6 | 多重采样目标上关掉多重采样（`!ms.enable && samples > 1`）走着色器变体 | 没处理 | 缺（多重采样目标还没走到） |
| 1.7 | 透明度转覆盖率 `ms.a2c` | 编译事实带了；后端管线没设 | 待核 |
| 1.8 | 顶点着色器没读的属性、没被保留属性用到的流：从键里清掉 | 核心把 `rp_S.attr` 全拷；绑定时按 `attr_mask` 只绑用到的流 | 待核：后端会不会因为没读的属性格式不支持而整条管线失败 |
| 1.9 | 合并通道的颜色槽重映射 `lmap` | 恒等 | 通道合并没接（不影响画面） |
| 1.10 | 变换反馈 / 几何着色器的特殊键 | 没接（记账） | 已知未接 |
