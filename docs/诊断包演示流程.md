# 诊断包演示流程（T77）

演示「模拟崩溃 → 重启询问 → 导出脱敏诊断」的可复现步骤。不依赖真机，不写入密钥或存档本体。

## ① Mac 模拟游戏进程崩溃

1. 确认启动器已创建应用数据目录；游戏运行日志写在 `<应用数据>/logs/host.log`（相对游戏库为 `<库目录>` 旁的私有目录，勿使用本机真实绝对路径写进反馈）。
2. 在一次游戏会话中，向当前 `host.log` **追加**一行崩溃标记后结束进程，例如：

   ```text
   【红】CRASH signal=SIGSEGV
   ```

3. 可用启动器任务页的「结束游戏」，或结束对应游戏子进程；不必强杀启动器本身。
4. iOS 原生侧（`ios/diag.m`）用「含 `【红】CRASH`」判定会话结局为 crash；Mac 导出走同一 host 日志约定。

## ② 启动器重启后如何触发询问（无需真机）

1. 完全退出并重新打开 Mac 启动器。
2. 若上次游戏进程异常结束，界面可提示「游戏进程异常退出，启动器仍可使用」；iOS 包在检测到上次未正常收尾时会询问是否发送诊断（`s2a_diag_prompt`）。本演示只需确认文案或弹窗出现，无需连接设备。
3. 也可在任务列表查看失败/中断任务的诊断卡片（含 summary / suggestion / logPath）。

## ③ 「导出诊断」产物与脱敏格式

1. 菜单或设置中点「导出诊断包…」，保存为用户自选路径下的 `S2Arm-诊断.zip`（须在应用数据与 `<库目录>` **之外**）。
2. ZIP 内常见成员：`manifest.json`、`jobs/*.txt`、`logs/*.log`（日志可能截尾）。`jobs` 保留诊断字段（code、severity、summary、suggestion、detail、stage、logPath、component、exitCode）。
3. 导出时统一脱敏：个人路径替换为标签（如 `[LIBRARY]`）、`password=` / 令牌等赋值为 `[REDACTED]`；`【红】CRASH` 行保留。勿在文档或反馈中粘贴设备唯一标识、签名团队编号或本机用户路径。
4. 离线复盘可用 `python3 tools/diagnostic_report.py '<诊断目录或ZIP>' --output '<新的报告目录>'`（见 `docs/测试报告与诊断收集.md`）；会话结局读 `observations["结局"]` / `termination`，不另造 `end` 字段。
