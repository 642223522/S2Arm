# 社区补丁拒收原因说明（D2 首片）

`graphics/cpatch/reasons.py` 只解释已经解析好的**一条原因字符串**，用于调用方展示中文说明。纯标准库，不读写文件、不扫目录、不联网、不读取补丁或游戏数据，不参与出包或运行时决策。

在仓库根目录的 Python 调用中：

```python
from graphics.cpatch.reasons import describe_reason

# row 是 C4（PR #522）既有 TSV 经 csv.DictReader(..., delimiter="\t") 读出的一行。
# 不把原始 plan.log 当作 CSV，也不在这里重写 C4 的严格解析。
detail = describe_reason(row["reason"])
# detail = {"code": ..., "message_zh": ..., "raw": row["reason"]}
```

`row` 的 `game/category/reason/count` 原样保留；不增加、合并或改算事件数。C4 的 TSV、严格五列 plan / 三列 prune 解析及报错合同均不变。本片没有接入启动器面板，没有定义面板 API、最终状态或补丁兼容性规则。

## 范围与返回值

现行生产者实际是 [pack/cpatch.py](../pack/cpatch.py) 的 `plan()`，不是 `graphics/cpatch` 目录。本片按 D2 派单在后者新增说明模块，没有搬迁或修改生产者。

| `code` | 对应 plan 分支 | `message_zh` |
| --- | --- | --- |
| `outside_image` | `写入 …+… 超出模块映像` | 这次筛选未收录：补丁要修改的位置超出了游戏程序模块的范围。 |
| `patch_conflict` | `与 … 改同一处 …+…` | 这次筛选未收录：这份补丁与另一份补丁修改了同一位置。 |
| `readonly_code_page` | `数据写入 … 落在代码段末页上（只读可执行，运行时写不了）` | 这次筛选未收录：补丁要修改的数据位于运行时不可写的代码页。 |
| `rewrite_conflict` | `改到我方改写点 …（宽屏点 / x18 等，两套改动叠在同一条指令上）` | 这次筛选未收录：补丁与 S2Arm 的代码改写位置重叠。 |
| `builtin_fps` | `本款已有我方帧率表（fps.tsv），社区帧率类不收` | 这次筛选未收录：游戏已有 S2Arm 帧率方案，不再收录社区帧率补丁。 |
| `module_limit` | `… 已有 64 份补丁（槽 2046 位数用尽）` | 这次筛选未收录：这个程序模块已达到 64 份补丁的上限。 |
| `unknown` | 其余字符串（含空串） | 此条拒收原因尚无对应说明，请查看原文。 |

完整固定文案与标点必须整串匹配。动态偏移/长度沿用生产者的十六进制/十进制写法；模块名不限定为 main/sdk，也不剥掉空格或 Unicode。`scan()` 对 INDEX 的 sha256 只是截前 16 字符，因此另一份补丁编号的摘要部分不能擅自限定为 16 位合法 hex；本模块只辨认模板，不验证该编号的真实性。

`raw` 逐字保留，不截断、不归一化，不从错误文字推断版本不匹配或提供未经验证的修复建议。每次返回新的字典；非字符串输入抛 `TypeError`。调用方显示原文时应使用普通文本而非 HTML/Markdown 执行语义；本函数不作 UI 转义，也不会把原文自行写入日志。

**所有以 `改写器缺口：` 开头的 prune 原因都为 `unknown`**，包括 C/Python 的固定细节和 Python `guarded()` 产生的动态异常，不能借用其中恰好出现的 plan 措辞误分类。极端情况下，若模块名本身让 plan 原因以同一前缀开头，单独的原因字符串无法分辨，也保守返回 `unknown`。未知不等于成功、可用或最终未收；原文仍可供排查。

`plan()` 可在 prune 后重跑并继续追加，先前未收的补丁也可能后来收下。因此说明刻意使用「这次筛选」，只解释事件，不宣称最终包里有没有该补丁。未登记的新生产文案保持 unknown，须核源码并补测试后才增加映射。
