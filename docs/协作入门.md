# 协作入门（新联合开发者）

新联合开发者接受仓库邀请后，维护方（众包线）照本文开一个欢迎 issue，标题「欢迎 <GitHub ID>：入门指引」。第 1–6 节是固定内容，原样贴；第 7 节的任务卡清单每次按当时 GitHub 上标「可领取」的卡重写，只列真实存在、写清难度和依赖的卡。

## 1. 项目是什么

S2Arm：把玩家自己的 Switch 游戏零配置移植到 iPhone、iPad、Mac，以及安卓、鸿蒙。现行方案是**直连**：游戏的 NVN / Vulkan / OpenGL 图形调用直接翻成 Metal（安卓上是 Vulkan），运行时着色器现编兜底。详见 [README](../README.zh-CN.md) 和 方案_快速通用模式。

## 2. 贡献规则（几条底线）

- **一个 PR 只做一件事**，目标几小时内合入；做不完就拆成几个能各自验收的 PR。PR 开了 24 小时没合入，巡检会提醒「合最新 main 或拆小」，48 小时标 `待拆`（协作循环 §3.4）。等维护方（接口、换链窗口、main 红）的不算，维护方会登记豁免。
- **main 红了先修 main**：你的合入把 main 弄红了，当轮修；修好之前，同一块不再往 main 上堆改动。
- **PR 正文写 `Closes #<卡号>`**（只交了一部分写 `Part of #<卡号>`）。中文「关闭 #N」或 T 号都不会自动关卡。
- 不直接推 `main`，只提 PR；只改卡面「文件边界」里写的目录。
- 评论和 PR 用中文写清：问题、改动、实际验证（「期望 → 实测」）、限制。负对照和射程（扫了几个、跑了几局）必写。

## 3. 入队前自检

```sh
git fetch origin main
bash tools/contrib_check.sh                        # 一级自检，10 分钟内，不需要我们的机器、真机、游戏文件；摘要原样贴进 PR
```

- 改到共享代码（`compat/tree`、`services/`）时，先跑 `bash tests/platform_scan_test.sh`，见第 4 节。
- 新加的单测要有门禁脚本调用（`python3 tools/test_wired_lint.py` 显示 0 处没接线）；门禁里跑不了的，在测试文件头写一行 `# 门禁手动：<原因>`。
- 环境原因跑不了的步骤（比如 Linux 上没有 Xcode），在 PR 里写明，维护方在 Mac 上补跑。

## 4. 平台边界

共享代码不新增平台判断（`OperatingSystem.IsXxx`）、平台库导入、对平台实现的直接引用，也不新增 `NativeLibrary.GetExport` 按名找导出。平台实现放 `platforms/<平台>/`，由平台装配登记进接缝（[架构_多终端](架构_多终端.md) §7）。不知道该走哪个接缝，就在 PR 里问，原生层给落点；不要自己加 `// 平台例外：` 绕过。

## 5. 许可与数据红线

- 项目许可 Apache-2.0；新依赖先核许可兼容（第三方清单见 [THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md)）。GPL 等 copyleft 不进分发产物。
- **游戏文件、固件、密钥、存档本体、资源包、社区补丁原文**一律不进仓库，也不贴进 PR / 评论；用自己的正版原件在本机测。
- 不提交设备唯一标识、Apple 团队编号、本机用户路径等个人信息（公开仓扫描会拦）。
- AI 辅助贡献见 [LLM 使用政策](../LLM_POLICY.md)。

## 6. 有问题在哪问

- 任务相关：在那张卡下回复，维护方每 10 分钟巡检一次，一般 30 分钟内回。
- PR 相关：直接在 PR 里问。
- 领卡：在卡下回 `/领取 <GitHub ID>`，写上预计的首个交付；做不下去回 `/放弃`。4 小时没有提交或进展回复，会被放回可领取。

## 7. 现在可认领的任务卡（欢迎帖里按当时情况重写）

按方向分组，每张写一句难度和依赖。来源：GitHub 上标签同时有 `任务`、`可领取` 的 issue（`gh issue list -l 任务 -l 可领取`）。已认领的不列；多人可领的（标 `可多人领`）写明。
