# 测试报告与诊断收集

R01 收集器离线读取诊断目录或 ZIP，输出统一 `schema_version: 1` 的 `report.json`、同模型生成的 `report.md` 和 `logs/0000.txt` 等脱敏文本。不需要设备、游戏或网络，不改原输入，也不写共享记分板。

```sh
python3 tools/diagnostic_report.py '<诊断目录或ZIP>' --output '<新的报告目录>'
python3 tools/diagnostic_report.py '<诊断目录或ZIP>' --output '<新的报告目录>' --metadata '<补充信息.json>'
# beta_intake 的显式独立模式，直接进入相同安全收集器：
python3 tools/beta_intake.py --diagnostic-report '<诊断目录或ZIP>' --output '<新的报告目录>'
```

`beta_intake.py --inbox …` 的默认 TSV 入库、去重及 `--report` 症状汇总保持原行为。独立模式不会先解压、写 TSV 或创建 inbox；不能和 legacy `--report` 同用。未选择独立模式时使用 `--output`/`--metadata` 会报错，显式空 metadata 参数也会转发并失败，不会静默忽略。Legacy 入库本身不提供本页描述的报告隐私保证。

输出目录必须不存在，且不能等于输入、位于输入内或是输入的祖先。重复执行须选新的输出目录。损坏的显式 metadata、危险 ZIP、超限输入和输出冲突以非零状态退出；错误不回显原始路径或异常内容。所有文件先写入输出父目录的临时目录，完整生成后用原子 mkdir 独占预留输出目录，再以不覆盖目标的硬链接发布文件，最后写入 `.complete` 完成标记。失败清理本次创建的文件，已有输出绝不覆盖；消费者只接受带完成标记的报告。

## 补充信息模板

字段放在以下 JSON 对象；可只填写已知项，缺项使用 `null`，报告列出 `missing_fields`。空白字符串及必需步骤的空列表也记缺失；明确没有更新/DLC的空数组和明确没有开关的空对象保留。缺少 host 日志、帧表、媒体时另列证据缺失及警告。同名补充字段覆盖 manifest，来源记为 `metadata:<字段>`；其余来源为 manifest 或 `missing`。旧 manifest 的 `app` 对应 `package`，`device.ios` 对应 `device.os`。不从 source 指纹猜测 Git commit，也不会把缩写包 commit 补成完整代码 commit。

```json
{
  "task": {"id": "R01", "platform": "macOS"},
  "code": {"commit": null},
  "package": {
    "id": null, "version": null, "commit": null, "sha256": null,
    "switches": {}, "signing": null, "build_id": null, "target_arch": null
  },
  "game": {"name": null, "id": null, "version": null, "updates": [], "dlc": []},
  "device": {"model": null, "soc": null, "memory": null, "os": null, "gpu_family": null},
  "test": {"steps": [], "scene": null, "route": null, "save_id": null},
  "reproduction": {"shortest_steps": [], "first_failure": null},
  "untested": {"items": [], "reason": null}
}
```

`code.commit` 应填写完整 Git commit；`package.commit` 是实际包提交，`package.sha256` 是包内容哈希。游戏 ID、正式 commit 和 SHA-256 保留。步骤、场景、路线与存档**标识**用于复现，不要提供存档内容。`updates`、`dlc` 描述实际安装版本；空数组表示明确没有，`null` 表示不知道。未测项目和原因需测试者明确补充，工具不会凭日志编造。

## 当前 iOS 导出格式

适配来源为 `ios/diag.m` 的 schema 1 `build_zip`。输入可以是平铺 ZIP、唯一顶层目录包裹的 ZIP 或已解包目录。ZIP 文件名在未标 UTF-8 时尝试按原始字节恢复 UTF-8，恢复前、恢复后和去除 wrapper 后都检查路径与重复目标；不会跳过未知成员的安全检查。目录 wrapper 仍通过可信目录 fd 打开，不跟随链接。

生产者字段窄映射如下，显式 metadata 优先：

| 生产者字段 | 报告字段 |
|---|---|
| `app.commit`（schema 1） | `code.commit`、`package.commit` |
| `app.bundle` / `app.version` | `package.id` / `package.version` |
| `app.build_id` | `package.build_id`（包号） |
| `app.pso_target` | `package.target_arch`（如 `applegpu_g18p.ios27`，保留逗号连接的原值） |
| `device.gpu_family` | `device.gpu_family` |
| `game.title_id` | `game.id` |
| `device.ios` | `device.os` |
| `device.ram_mb` | `device.memory`，明确带 MiB 单位 |

`game.build_id`、`game.pack_fp`、低功耗状态及 settings/sessions/MetricKit 摘要保存在可选 `producer` 信息并记录来源；包号与 GPU family 也保留原始 producer 信息。新报告字段 `package.build_id`、`package.target_arch`、`device.gpu_family` 在旧包未提供时列入缺失清单。目标架构取 `app.pso_target`，不会误取 `app.target_arch` 或据此推测 SoC。`pack_fp` 只是资源索引指纹，不能作为完整包 SHA；build ID 不代表游戏显示版本，GPU family 不代表 SoC。生产者没有提供的游戏版本、SoC 等仍为未知；`app.commit` 按原值保留，不从当前工具 HEAD 补全。

`producer.files` 保留生产者的 `path/bytes/truncated` 等原始声明；证据索引的 `truncated` 为已声明的布尔值，未声明时为 `null`。会话相关日志或帧表被标记截断（或截断声明不明确）时，记录 `evidence_completeness=partial`、截断来源和警告，整局格子为 `invalid`。头尾拼接的数据不能作为连续 55 秒窗口；原始明确崩溃仍保留为日志观测。生产者 sessions 摘要中的 exit/running 不被当作游戏通过。slim 导出缺少帧表时如实列缺失。

输入上限为解压后总计 256 MiB、单项 16 MiB、1000 项；覆盖生产者六份最多 8 MiB 诊断和二十份最多 4 MiB MetricKit 加 manifest 的预算。压缩后 30 MiB 不是解压后的安全预算。线程与 MetricKit 文本同样经过脱敏和索引。

`pack/jobs/diag.py` 的拉回根可能同时含多个 App 通道。请选具体 iOS ZIP 或具体 App 日志目录；本工具不会自动扫描多 App 父目录或递归收集全部 `diag/*.zip`。

## 会话、评分与 Mac 导出

每份 `host.log`、`host.prev*.log` 独立生成一个 `sessions` 项。会话记录可操作、画面、声音、帧时/卡顿、崩溃或终止、首遇现编、红行和既有格子的原值、状态与原因。日志来源、评分读数和缺失观测都保存在 JSON 和 Markdown。正常退出仅表示观察到退出行；没有退出/崩溃行记 `unknown`，不能推断被杀、卡死或通过。零字节或纯空白 host 日志记 `not_tested` 并列为缺执行证据；仅有这些文件时 `evidence.host_logs` 仍缺失，不会因缺 MARK 判游戏失败。

状态含义：`pass`/`fail` 来自既有证据判据；`not_tested` 表示缺少该项测试数据；`unknown` 表示无法确定；`invalid` 表示基础设施、测试条件或数据无效。评分复用 `score_cells` 纯函数及其 infra/test_unready/fps_basis 判据，采用临时树隔离，只复制同目录的允许诊断文件，不读取输入父目录 `r.txt` 或兄弟场景基线。报告不宣称拥有未提供的画幅真值或跨局比较证据。`host.prev*.log` 不使用当前 `frames.tsv`、功率或执行器日志。首遇扫描失败记未知，不记零；缺少心跳时，帧数/热状态/实占峰值记 `null`，`heartbeat_status=unknown`，这些是心跳观测而非帧表总计。坏帧表记无效，不伪造格子。

Mac 启动器的 `pack/jobs/library.diagnostics` 导出 ZIP 含 `jobs/*.txt` 与 `logs/*.log`。完整 JSON job 保留诊断中的 code、severity、summary、suggestion、detail、stage、logPath、component、exitCode 等字段；job 的 `state=completed` 只表示诊断任务结束，`game_result` 仍为 `unknown`。上游会截断 job 文本；无法解析时记 `parse_status=unavailable`，诊断为 `null`，发出警告并保留脱敏文本，不从残片猜结构化字段。

## 安全与索引

只收集根目录的 manifest/已知会话诊断文件、`logs` 下的诊断文本（含 `threads.txt`）、`metrickit/*.json`、`jobs/*.txt` 及 `shots`/`screenshots`/`videos`/`media` 下的媒体。目录遍历固定已打开的根目录 fd，使用相对可信父 fd 的 `stat`/`open`，逐层要求 `O_DIRECTORY|O_NOFOLLOW`；文件通过 `fstat` 校验身份、类型、大小和读前后变化并有界读取。即使枚举后祖先目录被替换为链接，也只读取原已打开的目录或安全拒绝。缺少安全目录 fd 能力的平台明确拒绝目录输入，不回退到绝对路径读取（仍可使用 ZIP 输入）。目录不跟随符号链接，不进入未列出的根目录或 keys/games/saves/resources/隐藏目录。ZIP 不调用 `extractall`，读取前验证全部成员，拒绝绝对路径、`..`、反斜杠、盘符、链接及重复规范化目标；最多 1000 项、单文件 16 MiB、总计 256 MiB（ZIP 含未收集成员也计入限额）。

脱敏统一由纯标准库模块 `tools/redact.py` 提供，导入时不读文件。公共接口为 `load_key_values(paths=None) -> frozenset[str]` 和 `redact_text(text, *, key_values=None, preserve_identity=False) -> str`。默认调用时读取 `~/.switch/prod.keys`、`title.keys`；文件不存在仍执行形状规则，其他读取错误导致失败，不会静默忽略。调用者可用 `load_key_values([])` 和 `key_values=frozenset()` 禁用默认读取；报告 CLI 可重复传 `--keys '<密钥文件>'` 显式指定路径。密钥文件只用于加载待遮罩值，不加入报告。

任意标识（含数字开头的 rights ID）赋值为至少 32 位十六进制时，整行值均被遮罩，不依赖键名清单。已加载值在任何上下文按长值优先替换，十六进制忽略大小写；正式 SHA/commit 身份字段的豁免也不能绕过已知密钥值。开发回归只使用临时随机假密钥并 mock 默认路径，包括 CLI 子进程；不改变 HOME。

新输出文本和索引名称会脱敏结构化密码/令牌/通用 `*_key`/titlekek/设备唯一标识、原始日志中连续 64 位及以上十六进制材料、Authorization（含带前缀的嵌入 JSON）、单双引号包裹且包含空格或转义引号的完整秘密值、URL 用户密码及敏感 query、个人路径。Markdown 按文本转义 HTML、控制字符、表格及链接语法。日志用数字文件名，索引保留脱敏相对位置、类型、原始大小、原始 SHA-256、可用性和脱敏副本位置。SHA 用于对照原证据，脱敏副本内容不同，不能用副本重算原始哈希。

截图与录像仅计算索引，**不复制，也不自动脱敏**；`availability=indexed_only`、`sanitized_path=null`。分享前人工审查画面、声音、游戏内账户名及任意未标记的自由文本。收集器针对已知秘密结构和模式处理，不代替测试者对自由文本内容的审查。请只提供专用诊断导出，不要把游戏、固件、密钥或存档放入输入。

## 验证范围

```sh
bash tests/diagnostic_report_test.sh
bash tests/beta_intake_test.sh
bash tests/score_test.sh
bash tests/firstuse_test.sh
python3 tools/diagnostic_report.py --help
```

自动化使用合成文本与占位媒体，包括真实 Mac 导出函数产生的 ZIP、截断 job、恶意输入、隐私哨兵、评分一致性、隔离与 CLI 往返。它验证报告工具逻辑，不证明任何游戏在真实设备可玩。

当前生产者兼容的验证采用独立写死的合成 schema 1 数据，并真实构造 UTF-8 flag 为零的中文 ZIP；没有编译或运行 iOS 导出器。生产代码修改仅在报告收集器；会话解析和评分复用已有工具。未进行真机游戏测试或完整门禁，范围外生产者问题仅作说明。
