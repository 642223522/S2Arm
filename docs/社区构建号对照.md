# 社区构建号只读事实表（C2）

```sh
python3 tools/community_build_compare.py <INDEX.tsv> <unpack.tsv> [<unpack.tsv>…] > comparison.tsv
bash tests/community_build_compare_test.sh
```

这是独立的**人读元数据对照**，没有接入社区面板、出包或补丁应用器，列名不是已确认的消费者 API。只打开命令行逐个指定的文件；不遍历目录、不联网、不读取 INDEX `path` 指向的补丁、NSO、游戏或邻居文件，也不修改输入。不要把输出重定向到任一输入：shell 会在工具启动前截断文件，工具无法撤销。

## 输入与边界

- INDEX 是严格 UTF-8 的带表头 TSV，需唯一的 `title_id`、`build_id` 列；其他唯一、非空列名允许但不用于判定。支持标准 CSV 双引号转义（分隔符 TAB），只跳过**表头前**以 `#` 开头的注释。不忽略空记录、截断记录、额外字段或引号损坏。只有表头合法；完全空的 INDEX 是错误。
- unpack 是 `pack/nx_unpack/Program.cs` 实际写的 `键<TAB>值`，**不是**带表头 CSV，没有引号转义；LF / CRLF 均可。键只能出现一次，恰两列。`builds` 的空格分隔 `模块:记录值` 中只认精确 `main`，不认 `Main`、`sdk`、`domain`；重复 `main` 即使值相同也拒绝。空格连续出现允许；缺冒号、空模块名、未转义 TAB / 换行损坏结构不猜边界。`--nacp-only` 可以不写 `builds`，此时明确缺主程序记录。
- 关联只看**完整 16 位 ASCII hex** `title_id`，忽略大小写，不合并本体／更新／DLC，也不根据版本名、文件名或前 13 位关联。同号多个 unpack 分别出行，不选“最新”；INDEX 重复行不去重，不按 `in_pack`、补丁类型或版本过滤。
- 两侧构建值保留原字符串、大小写和字符长度，不剥空白、`0x` 或尾部 `00`，不补零、不补后缀。可比较文本域明确限定为 **16–64 个 ASCII hex 字符且长度为偶数**（对应完整字节）；域外记录标 `invalid`，并不声称所有社区格式都只使用此域。这一选择参考仓内 cpatch 的构建标识边界，不继承它的应用判据。`Program.cs` 实际记录的是 NSO 头 `0x40` 起 **16 字节 / 32 hex**，不是完整 NSO 标识证明。
- 文件缺失、读取失败、非法 UTF-8、NUL、空 unpack、重复键／main、TSV 结构错误：stderr 报错，退出 **2**，stdout 为空。解析完成后才输出，后一个文件出错也不会留下半份表。缺少／非法字段值则是表中显式事实，完整报告退出 **0**；0 只表示报告生成成功。

输入格式依据限于仓内 `pack/nx_unpack/Program.cs`、`pack/jobs/community.py` 与 `pack/jobs/tests/test_community.py`、`pack/cpatch.py`；不从私有资源推导格式。

## 输出

stdout 为 UTF-8 TSV，特殊 TAB、换行、双引号由 CSV 规则转义。按 INDEX 记录输入顺序，再按 unpack 命令行顺序；最后按命令行顺序列出没有关联 INDEX 的 unpack。

| 列 | 含义 |
| --- | --- |
| `index_row` | INDEX 数据记录序号，从 1 开始，不是物理行号；重复行仍各占一个序号 |
| `index_title_id` / `unpack_title_id` | 各侧实际记录的程序号，不改大小写 |
| `index_build_id` / `unpack_main_build_id` | 各侧实际构建字符串，只取 unpack 的 main |
| `index_chars` / `unpack_chars` | 原字符串的字符数；非法值也如实给长度，并非字节数或有效 hex 位数 |
| `status` / `reason` | 下述事实分类及原因 |
| `index_path` / `unpack_path` | 命令行中对应元数据路径；INDEX 行可据序号回查，**不是** INDEX 内的补丁 path |

没有对应侧时该侧所有列留空；存在对应侧但构建值为空时，字符串为空、长度为 `0`。同一行多处缺失／非法时原因按 `index` 程序号 → 构建值 → `unpack` 程序号 → 构建值次序报告首项，各侧原值仍完整保留。

| status | 精确含义 |
| --- | --- |
| `same_recorded_128` | 两侧均为 32 hex，大小写归一后全等；reason=`equal_32_hex_records`。只证明已记录的 128 位相同 |
| `prefix_only` | 较短记录与较长记录的已知前缀相同（`equal_known_prefix_only`）；或两个相同但非 32 hex 的记录（`equal_records_non128`）。保守保留此分类，不冒充已核完整身份 |
| `different` | 两个合法记录在共同已知范围内出现不同字符（`recorded_hex_differ`）；**会比较超过 32 位的已记录尾部** |
| `missing` | 程序号／构建值缺失，或未找到完整同号的另一侧。reason 为 `index_title_missing`、`unpack_title_missing`、`index_build_missing`、`unpack_main_missing`、`unpack_title_not_found`、`index_title_not_found` |
| `invalid` | 非法程序号或构建值。reason 为 `index_title_invalid`、`unpack_title_invalid`、`index_build_invalid`、`unpack_build_invalid` |

**任何状态都不是“兼容”“可用”“可应用”。** INDEX 记录不证明补丁内容或它针对哪个模块，unpack 也不证明当前游戏文件仍与元数据一致；本工具不读取二者来核验。完整身份验证、跨版本定位、面板行为和实际应用仍不在本片范围。没有校验和／结束标记的文件即使语法合法，也无法由此证明未被截断或是最新版本。
