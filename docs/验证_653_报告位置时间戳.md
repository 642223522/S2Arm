# #653 报告位置时间戳：宿主验证与待证边界

依据维护者裁定：<https://github.com/jhaizhou-ops/S2Arm/issues/653#issuecomment-6918748835>。

## 机制

契约 v9 增加命令段所有的 64 个报告槽与独立有效位。回放不预扫，执行到报告时记录实际段和槽；中途提交只复制该段结果，最终完成回调先写记录再发布围栏。超过 64 条或能力不支持走既有 guest tick，并由 `rp_timestamp_fallback_take()` 计数。失败段不写成功结果，FAULT 只写有效槽；0 是有效样本。

Vulkan 首次报告创建独立查询池，前置命令缓冲 reset，主缓冲在报告位置分别以 TOP/BOTTOM 写槽。只有设备与 CLOCK_MONOTONIC 校准均可用才公开能力。完成回调返回校准 host ns，资源保持到回调结束；不把原始计数、duration 或 CPU completion 当成采样值。整数位宽回绕有半周期歧义时判无效。

共用时钟层按现有 guest 基点和暂停偏移换算。仅保存当前映射区间：异步样本跨外层 freeze/thaw 时明确无效，不用新偏移伪造历史。此限制必须由维护者评审，不宣称支持历史映射。legacy Metal 未实现 nvn_gpu 契约，本批在真实报告入口累计并记录 unsupported，保留旧回填；没有新增假成功后端。

## 实际宿主证据（Linux CPU，无游戏数据）

- 先红：只加两个同段报告测试，旧核心在 distinct sample/type/call 检查红。

- `runtime/tests/t_os.c`：47/47（含新会话 epoch 重置）；CPU-now 替换负控 10 项红，取消映射区间校验负控 4 项红。

- Vulkan 后端 C11 `-Wall -Wextra -Werror -fsyntax-only` 通过。
